# Alear030 文档漂移检查

检查文档与代码现场是否脱节。硬边界是**严格只读**:不写任何文件、不改 git 状态(add/commit/stash/checkout 都不行)、不跑 `python main.py`、不调项目自身的模型 API。只汇报,不做任何修复——处理方式由用户决定。

## 检查范围（默认核心文档）

- 顶层 12 篇:README(.en)、AGENTS.md、CLAUDE.md、CHANGELOG.md、COLLABORATION(.en)、CONTRIBUTING(.en)、SECURITY(.en)、THIRD_PARTY_NOTICES.md
- docs/ 全部(index、ARCHITECTURE、CONFIGURATION、EXTENDING 及 design/、modules/、research/、observations/)
- .cursor/rules/ 全部 .mdc

范围可按用户指令增减;prompt/tool 提示词 md 和 SKILL.md 默认不查(体量大)。

**docs/observations/ 只查结构性漂移,不进行为描述漂移口径。** 观察文描述的是外部系统,拿本仓代码去校验它的断言必然全是假阳性。对观察文只做两件事:相对链接可达性,以及「观察日期 + 证据等级标注」这两个体裁必填项在不在。文里的技术断言一律不判、不列问题。

## 流程

1. 先 `git status --short` 取脏文件清单,供第 4 步联动。
2. 结构性漂移**先机械核对再下结论**:提取文档引用的文件路径、目录、入口、技能名、模板/hook 计数、链接目标,用 `git ls-files` 和目录列举核对存在性,压低误报。
3. 行为漂移只比「文档明确断言」与「现场代码明显矛盾」的点,引文与代码抽样逐字核对;运行行为以现场代码、注册器和配置为准,不以任何文档(含 CLAUDE.md/AGENTS.md)为准。
4. 脏文件联动:某条判定依赖当前有未提交改动的代码文件时,跳过判定、不列入问题,改在警示区列出文档名+涉及脏文件,注明「等代码落定后再查」。
5. 笔误与过期:错别字、失效相对链接(核对链接目标文件)、已删除技能/命令的过时说法。
6. 扩展建议:代码有机制但无同类型文档覆盖时,只建议补到哪篇文档哪个部分,不实施。

语义比对可派 Explore 子代理并行(建议三组:顶层文档、docs 与 .cursor/rules、行为比对与扩展建议),子代理同样只读。

## 高发形态与已知例外

- 最常见的是「登记未同步」:新技能/规则/模板/hook 加入后,旧文档里的计数没跟上。技能数核对 `.claude/skills/` 下有 SKILL.md 的目录,规则数核对 `.cursor/rules/`。
- 中英对照文档(.md 与 .en.md)必须双侧同改;检查时区分「双侧同步过期」与「单侧漏改」。
- CHANGELOG 历史版本块引用的是当时路径,事后迁移不算缺陷,只提示读者会落空。
- 不得报告的已知例外:存量兼容 typo(config 的 `MEMORTY`,memory_storage_core 的 `loker`/`slef`);`mcp_client/mcp.json` 缺失属预期(仅 .example 入库);`z_ccstudy/`、`z_old_code/` 等本地目录在 worktree 缺失不算漂移。

## 报告格式（中文）

1. 摘要:检查文档数、确认问题数(按口径分)、警示数。
2. 分文档发现清单:每条含口径类别、`文件:行号`、证据、一句话说明。
3. ⚠️ 警示区:因未提交代码跳过的判定及涉及脏文件。
4. 扩展建议列表。
