# memory_recall 系统性测试方法论

## 核心原则

- **变量控制**：同一轮对比中，除待测变量外，key_words、search_target、top_k 必须完全一致
- **先圈定再精确**：基于系统注入的历史时间线，圈定 3~5 个候选 session_ids
- **渐进复杂度**：从单次双模式对比 → 多变量矩阵测试 → plan 模式规模化执行 → 最终报告
- **结果驱动**：基于实际返回的 score 和内容相关性做判断，而非预期推测
- **透明汇报**：向用户展示完整对比数据，包括命中的 session_id、内容摘要、分数

## 工具

- `memory_recall`：核心检索工具，注意 session_ids 传纯时间戳格式（去掉 "session" 前缀）
- `plan_design` / `plan_mode_on` / `plan_update` / `plan_mode_off`：规模化测试时使用
- `session_slice`：需要查看原文时使用
- `ask_user_question`：需要确认方向时使用

## 三种执行模式

### 模式一：单次双模式对比（快速模式）

适用于用户指定了一个具体关键词/意图，仅需做一次带/不带 session_ids 的对比。

**执行步骤：**

**Step 1：确认测试关键词和目标**
向用户确认本次测试的关键词和搜索意图。如果用户只说了关键词，帮助补全 search_target（用一两句话描述要查询的目标）。

**Step 2：圈定候选 session_ids**
基于历史时间线，找出与关键词最相关的 3~5 个 session：
- 看时间线中每个 session 的关键词和叙事线索，判断哪些 session 可能包含目标内容
- 优先级：thread 描述或 key_words 中直接包含用户关键词的 session > 语义上沾边的 session
- 拿不准时可以多挑几个候选，但不要把所有沾边的都传进去——传太多会让 session_ids 退化成变相全量扫描
- 如果时间线里找不到明显相关的候选，不要硬猜，后续直接走全量扫描

**Step 3：执行双模式调用**

并行执行两次调用，唯一变量是 session_ids：

第一次（带 session_ids）：
```
memory_recall(key_words, search_target, top_k=5, session_ids=[...])
```

第二次（不带 session_ids，全量扫描）：
```
memory_recall(key_words, search_target, top_k=5)
```

⚠️ 两次调用的 key_words、search_target、top_k 必须完全一致。
⚠️ session_ids 使用纯时间戳格式（如 `20260704_200011`），不要传 "session" 前缀。

**Step 4：对比分析**

从以下维度对比：

| 维度 | 说明 |
|------|------|
| 命中数 | 各自返回了多少条结果 |
| 最高分 | 最高 cosine 相似度 |
| 前3精准度 | 前3条结果的内容是否真正与目标相关，还是语义漂移 |
| 覆盖率 | 是否覆盖关键内容，还是遗漏了重要片段 |
| 分数虚高现象 | 全量扫描中是否有高分但实际不相关的结果 |

**Step 5：分析差异原因**

- 带 session_ids 结果更好 → 时间线预筛选有效，范围锁定过滤了语义噪音
- 带 session_ids 漏掉高分片段 → 预筛选范围不当，时间线描述质量不足
- 全量扫描更好 → 时间线质量不足以支撑预筛选，或关键词特异性强
- 两者结果相似 → 关键词特异性强，范围限制影响不大

**Step 6：向用户汇报**

用对比表格展示两次结果，给出综合判断和差异原因分析。

### 模式二：多维度矩阵测试（全面模式）

适用于用户要求"全面测试"、"多维度测试"、"多组对比"时，同时揭示多个变量的独立贡献与交互效应。

**核心变量：**

| 变量 | 说明 | 取值 |
|:----|:----|:----|
| **K** | key_words | 有（具体关键词）/ 无（空数组） |
| **S** | session_ids | 有（圈定候选）/ 无（全量扫描） |
| **T** | search_target | 精确（一两句话描述意图）/ 模糊（宽泛描述） |
| **语义强度** | key_words 本身的特异性 | 高特异性 / 中间语义 / 宽泛主题 / 语义基元类 / 真噪音词 |
| **目标类型** | 要查的内容性质 | 事实性问题 / 开放性问题 |

**标准测试组设计：**

**A组——K×S 交叉矩阵**（固定 T 模糊，4 次调用）

| 编号 | key_words | session_ids | search_target |
|:---:|:---------:|:-----------:|:------------|
| A1 | ✅ 有 | ✅ 有 | 模糊 |
| A2 | ✅ 有 | ❌ 无 | 模糊 |
| A3 | ❌ 无 | ❌ 无 | 模糊 |
| A4 | ❌ 无 | ✅ 有 | 模糊 |

**B组——search_target 精度组**（4 次调用）

| 编号 | key_words | session_ids | search_target |
|:---:|:---------:|:-----------:|:------------|
| B1 | ✅ 有 | ❌ 无 | 精确 |
| B2 | ✅ 有 | ❌ 无 | 模糊 |
| B3 | ❌ 无 | ✅ 有 | 精确 |
| B4 | ❌ 无 | ✅ 有 | 模糊 |

**C组——语义类型光谱组**（10 次调用，5种类型 × 带/不带ids）

| 类型 | 示例 | 说明 |
|:----|:----|:----|
| 高特异性 | 「unsummary_pointer」「compress hook」 | 专有名词/稀有概念 |
| 中间语义 | 「残缺」「自举」「递归」 | 常见但可定位 |
| 宽泛主题 | 「变化」「感受」「问题」 | 常见且范围广 |
| 语义基元类 | 「东西」「方式」「结果」 | 对话摘要中的高频基元 |
| 真噪音词 | 「铅笔」「冰箱」「红色」 | 完全不相关的日常词 |

**D组——目标类型组**（2 次调用，固定中间语义 kw + 精确 T + 带ids）

| 编号 | 目标类型 | 示例 |
|:---:|:--------|:----|
| D1 | 事实性问题 | "何时开始学Python" |
| D2 | 开放性问题 | "对系统的感受和期待" |

**执行方式：** 所有调用可以并行执行，一组内的调用使用完全相同的 key_words 和 search_target（除变量本身外）。

**对比分析：** 除模式一的维度外，额外关注：
- 变量独立贡献排名：哪个变量对结果影响最大
- 交互效应：K 和 T 是否存在互补替补关系
- 最佳/最差参数组合

### 模式三：Plan 模式执行（规模化模式）

适用于测试方案足够全面（如完整的多维度矩阵）、需要分步执行并输出可验收的中间产物时。

**执行步骤：**

**Step 1：用 plan_design 创建结构化计划**
- 包含完整的步骤序列（通常 5~7 步）
- 每一步有明确的验收标准和产出物
- 产出物统一存放于 plan 产出目录

**Step 2：用户确认后 plan_mode_on**
- 展示计划内容给用户
- 用户确认同意后调用 plan_mode_on 进入执行模式

**Step 3：按步骤依次执行**
- 每步先执行该步骤的全部调用
- 完成后输出中间产物（文档/报告/分析文件）
- 用 plan_update 标记状态为 done
- 等待系统注入下一步

**Step 4：撰写最终报告**
- 整合全部步骤的发现
- 产出结构化报告（机制发现 + 决策矩阵 + 黄金法则）
- 报告存放于 plan 产出目录

**Step 5：plan_mode_off 收尾**
- 全部步骤执行完毕并更新状态后调用
- 输出一句话总结

## 已知核心发现与内置经验

以下发现来自大量测试积累，可直接作为分析的参考依据：

### 五大核心机制

1. **key_words 是主锚点，但可以被精确 search_target 替代**——二者在向量化时拼接构成锚点向量，一个强时另一个可弱，只有同时弱才崩盘（无K+模糊T时前3精准度可降至0/3）

2. **session_ids 不是"范围限制器"，而是"噪音过滤器"**——语义基元类场景下全量扫描会被无处不在的语义邻居淹没，带 session_ids 强制缩小候选池让目标浮出水面。分数高低不反映精准度——低分但精准 vs 高分但漂移

3. **分数是相对距离，不是绝对可信度**——噪音词最高分与精准命中最高分可能仅差 0.09。score 只能在同一调用内比较相对排名，不能跨调用比较

4. **K 和 T 是互补替补关系（负交互效应）**——一个变量强时另一个变量的变化不影响结果，只有两个同时弱才崩盘

5. **时间线预筛选的双刃剑效应**——净效益 = 关键词特异性 × 目标模糊度。词越泛、目标越宽，预筛选价值越大；词越专、目标越精确，预筛选风险越大。当搜索内容跨越较长的时间段时，双模式可能呈现**时间阶段互补**——全量扫描覆盖早期、带 session_ids 聚焦中后期，组合使用才能获得完整画面

### 快速决策矩阵

| 场景 | key_words | session_ids | search_target |
|:----|:---------:|:-----------:|:-------------|
| 记得稀有概念 | 直接使用专有名词 | 不传 | 简短描述 |
| 只记得模糊词（如「东西」「方式」） | 尽量想具体的 | ✅ 必须传 | 精确描述意图 |
| 查具体事实 | 尽量具体 | ❌ 不传（走全量） | 精确提问 |
| 完全不知道用啥关键词 | 至少试一个宽泛词 | 不传 | 清晰描述目标 |
| 关键词和意图都很模糊 | 至少传宽泛词 | 不传 | 至少清晰一点 |
| 三个参数都模糊 | ❌ 空数组 | ❌ 不传 | ❌ 模糊 → 极低质量 |
| 跨越长周期主题 | 尽量具体 | 双模式都要做 | 精确描述 |

### 七条黄金法则

1. 先问"我要找的是什么类型的词？"——决定是否传 session_ids
2. key_words 和 search_target 要互补，不能同时弱
3. 不要相信分数的绝对值——只看同一组内的排名
4. 时间线预筛选是双刃剑——窄圈定适合语义基元类，宽圈定适合大多数场景，不圈定适合事实性问题
5. 事实性问题用全量，开放性问题用 ids
6. 无法确定时，宁可多传 session_ids 也不要少传
7. 跨越长周期的主题，双模式组合使用才能获得完整演进脉络
