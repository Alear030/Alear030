## 体裁

`docs/` 下的文档分三类：**四级递进**讲这个项目自己，**两类旁支**分别讲项目外部的系统、以及一次改动走过的来路。新增文档先归位再动笔。

### 四级递进（对象是 Alear030 自己）

- **总览文档**（`docs/` 根）：跨模块的整体说明，面向第一次读这个项目的人
- **模块机制文档**（`docs/modules/<module>.md`）：单个模块「现在是什么样」，文件名对齐 [架构文档](ARCHITECTURE.md) 「目录结构」里的模块名
- **设计叙事文档**（`docs/design/<topic>.md`）：单个机制「为什么长成这样」，和机制文档解耦
- **研究文档**（`docs/research/<topic>.md`）：一个**还没有定论**的问题——假设、实测数据、结论，以及被推翻的假设和撤回的结论

前三层讲的都是已经做成的东西，研究文档讲的是方向性或者还没落盘或者长期跟踪记录的东西，所以它有两个不一样的地方：**允许没有结论**，以及**保留出错的过程**。推翻自己的假设、撤回基于错误方法得出的结论，都留在文里而不是删掉重写——一条结论怎么来的，和结论本身一样重要——所以如果真有人认真查看了这里面的文档，可能需要有自己的判断或者多一点质疑。

研究出了结论之后，要么催生一条改动型 issue 去落地，要么沉淀进对应的设计叙事或模块机制文档；研究文档本身不承担「当前实现是什么样」的说明责任。

### 旁支：观察文档（对象是外部系统）

- **观察文档**（`docs/observations/<topic>.md`）：**别人家的系统，怎么解一个我也在解的问题**

它不是「第五级」。前四级共享同一条轴——对象都是本项目，按「是什么 → 为什么 → 还没定论」递进；观察换掉的是**对象**，不是确定性档位。

准入判据是三条全中：①对象在项目外部；②有本机可复现的一手证据，不是聊天里的转述；③有对照价值，即它解的是我也在解的问题。只是有趣、但没有对照价值的见闻不进 `docs/`。

它还有一条前四级都没有的约束：**没有「以代码为准」可以兜底**——证据不在本仓库里，而且被观察方会自己改。替代的兜底是三件事：标明观察日期与被观察版本、把「怎么观察到的」写进正文让人能自己复现、给每条断言标注证据等级——一手（本机文件或可复现行为）／二手（被观察系统自己的说法，**这不构成验证**）／三手（推断）。

和研究文档一样，允许没有结论、保留猜错的过程。区别在出口：研究出了结论要落地成 issue 或沉淀进别的文档，**观察只记录、不立项**——观察若催生了自家改动，那条改动自己走 issue 或设计叙事，观察文不承担。

### 旁支：复盘文档（对象是一次改动的来路）

- **复盘文档**（`docs/retrospective/<topic>.md`）：**一件事怎么一路变成了另一件事——起点是什么，中途牵出了什么，最后落地的又是什么**

它同样不是「第五级」。四级递进的对象是这个项目，观察的对象是别人家的系统，复盘换掉的对象是**过程本身**。设计叙事讲的是一个机制为什么长成这样，落点在机制；复盘讲的是一条改动链路怎么走成这样，落点在这条链路——它经常横跨好几个模块，而且往往终点和起点不是一件事。

之所以要单独留一类：一个改动真正的代价常常不在它自己那几行，而在它牵出来的东西。这部分信息不属于任何一个模块，写进谁的机制文档都不合适，但它恰恰是最难重新想起来的。

准入判据三条全中：①记的是链路怎么走的，不是机制怎么运作——机制部分属于设计叙事，这里只留过程；②必须挂在可查的真实痕迹上（commit、issue、具体代码行），不是抽象的经验之谈；③**必须保留至少一处中途被推翻的判断**——缺这一条就会写成事后合理化，每一步都显得很英明，而那既不是当时的样子，也就看不出这条路到底拐在哪。

出口和观察一样：**复盘只记录、不立项**。复盘里翻出来的待办各自走 issue，复盘文不承担落地责任。

只有已经写出实质内容的文档才会出现在下面的列表里；尚未成文的模块不预留占位链接。
