## memory_recall 工具说明

用途: 基于语义向量检索，从历史 session 的对话切片中回忆相关内容。检索范围是除当前 session 外的全部历史 session，按余弦相似度对切片摘要排序后返回最相关的结果。

### 何时使用:
- 用户提到之前讨论过的话题、做过的决定、定下的方案，需要回忆细节时
- 需要确认过去是否处理过类似问题、踩过什么坑、给过什么结论时
- 执行任务前需要了解相关的历史背景和上下文时
- 用户明确要求"回忆一下"、"之前说的是什么"、"上次是怎么处理的"时
- 当你觉得这件事情好像需要回忆一下的时候

### 何时不要使用:
- 只需要当前 session 内的内容 → 直接看上下文，不必调用
- 已知具体 session_id，只是想看某段对话的完整原文 → 直接用 session_slice 工具
- 目标模糊到连关键词都想不出来 → 先向用户确认要回忆的主题，而不是盲目搜索

### 参数说明:
- key_words (必填): 查询关键词，3-5个，尽量覆盖核心概念/专有名词，会与 search_target 拼接后一起向量化
- search_target (必填): 用一两句话描述你要查询的目标或意图，越具体检索越精准
- top_k (必填): 返回结果数量。精确查询建议 2-3 个；主题宽泛或关键词把握不准时建议 3-5 个
- session_ids (可选): 候选 session_id 列表，传入后只在这些 session 内检索，不遍历全部历史。**必须传纯时间戳 ID**，例如时间线展示的 `session20260704_200011` 应传为 `20260704_200011`；`session` 只是时间线的展示前缀，不属于实际 session_id。结合系统注入的历史时间线(每条带 session_id/thread/key_words)圈定候选范围：
  - 时间线的 thread 是对整个 session 的粗粒度叙事总结，语义匹配出的"最像"那一条不一定就是真正命中的 session；建议挑 3-5 个看起来最可能相关的候选一起传入，不要只传单个最像的那条，否则范围留窄了会漏召回
  - 关键词本身比较宽泛、常见时，时间线里沾边的 session 可能不少，这种情况更要按可能性筛出最相关的 3-5 个，而不是把所有沾边的都传进去——传太多会让 session_ids 退化成变相全量扫描，失去缩小范围的意义
  - 拿不准该圈定哪些 session、或时间线里找不到明显相关的线索，就不传这个参数，走全量扫描，不要为了"圈定范围"硬猜一个不确定的候选
  - 此外，圈定范围时除语义相关外还应结合**下方时效性引导**考虑目标时段--timeline 已按时间顺序注入上下文，它是定位"该回忆哪个时段"的时间地图，而不只是语义索引

### 时效性引导:

timeline 已按发生顺序注入你的上下文(每条含 session_id/keywords/summary/叙事线索)。memory_recall 的返回结果不带显式时间，但 session_id 本身就是时间戳--形如 YYYYMMDD_HHMMSS(如 20260101_120000)，前 8 位是日期。你有两个时间信息源：返回结果里的 session_id，以及上下文里已注入的 timeline。召回前后都要主动用它们做时效判断。

**调用前：先判查询的时效类型，再圈 session_ids**

用户的问题通常落在下面四类之一，圈定 session_ids 时应按类型倾斜目标时段(但窄话题/专有名词不要硬按时段筛，会漏召回):

- 近期偏好型("上次怎么处理""现在还这样吗""最近") -> 优先圈近段 session
- 起源偏好型("一开始的初衷""最早怎么定义""最初") -> 优先圈早期 session
- 时段定位型(用户点了具体时间或事件，"上个月那次""之前某个具体话题") -> 在 timeline 里定位该时段，把对应 session 圈入
- 时间无关型(项目中特有的术语、某次给方案起的名字、特定概念的命名) -> 忽略时间，正常语义圈定即可，不要用时段筛

**调用后：从 session_id 读时间，按类型验时效**

拿到结果后，从每条 session_id 前 8 位读出日期，结合查询的时效类型做以下判断:

- 近期偏好型命中早期结果 -> 可能存在更新版本，考虑再 recall 一次近段确认是否被推翻，不要直接拿旧结论当现状
- 同一主题命中多个时段 -> 识别方案/认知的演进(早期版本 vs 最近版本)，向用户说明演进而非只报最近或最早那一条
- 易过期内容(市场行情/招聘信息/价格/政策) -> 主动标注"这是 X 时的结论，距今约 N，需重新确认是否仍有效"，不要当现成事实直接复用

**反直觉提醒**

时段匹配 ≠ 切片命中：session 级别时间对得上不代表切片级别语义相关。timeline 里时间位置最像目标时段的那条 session，不等于真正命中的 session--仍以 embedding score 为准，时段只是圈定候选的辅助维度，不是命中判据。

### 调用后:
- 返回结果是按相关性 (score，0-1 的余弦相似度) 降序排列的切片列表，每条包含 session_id / topic / start_round / end_round / key_words / summary_detail / score
- summary_detail 只是该片段的摘要，不是对话原文。如需查看原始对话内容，用返回的 session_id + start_round + end_round 调用 session_slice 工具获取原文
- 若返回结果 score 普遍偏低，或摘要内容明显和查询目标不符，说明历史 session 里大概率没有相关内容，不要强行套用低相关结果，也不要反复换关键词硬找
- 解读结果时还需结合**上方时效性引导**做时效判断--尤其是易过期内容，不要把历史结论当现状直接复用

### 注意事项:
- 检索范围不包含当前 session，避免召回当前对话内容形成自我循环
- 基于 embedding 语义相似度检索，同义表达也可能命中，但关键词仍建议贴近原始表述以提高召回质量
- 不传 session_ids 时会遍历全部历史 session 的切片计算相似度，session 数量较多时耗时会增加，不建议高频重复调用；传入 session_ids 可显著缩短耗时
