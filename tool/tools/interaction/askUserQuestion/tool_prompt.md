## ask_user_question 工具说明

用途: 当缺少会实质改变后续路径的用户目标、偏好、边界或取舍时，向用户发起一个或多个问题并等待结构化回答。

### 何时使用:
- 路径会分叉，且答案会锁死后续设计或实现（做 A 还是 B、先验证哪一层、偏好会约束后续选型）
- 已形成 2–4 个真实、互斥且可执行的方向，需要用户拍板
- 几道题的答案会互相约束、必须一次收齐时，才在同一次调用里放多题

### 何时不要使用:
- 能读代码、搜索、记忆召回或合理默认值就能定 → 先自己做，不必问
- 命名、排版、实现细节等低风险小决定 → 直接拍板
- 还没探索清楚就甩大而空的问题 → 先探索，再把真正分歧炼成题
- 把本该自己做的决定推回用户 → 能合理自决就自决
- 用户只说「测一下工具」时，仍要问**真实有分叉的题**；不要问「你想看什么测试效果」这类自指空转

### 参数说明:
唯一参数 `question_info`（必填）: 非空对象数组。每一项是一道题；**单题也必须带完整字段，尤其是 `header`**。

每项字段：
- `header`（必填）: 非空短字符串，顶部 tab 标签用；建议 2–8 字（如「终端」「风格」），不要整句题干。单题也不能省。
- `question`（必填）: 非空字符串，本题完整题干（写清分歧与影响）。
- `multi-option`（可选）: 布尔。`true` 为多选；缺省或 `false` 为单选。只能走一条路时不要写 `true`。
- `options`（必填）: 非空数组，建议 2–4 项。每项含：
  - `label`（必填）: 非空字符串
  - `description`（建议）: 说明取舍或适用条件

TUI 会在选项末尾自动挂自行输入行；**不要**在 `options` 里再加「其他 / 自行输入」。

单题调用示例：
```json
{
  "question_info": [
    {
      "header": "终端",
      "question": "优先用哪种终端交互方式？这会影响后续输入与确认流程。",
      "options": [
        {"label": "结构化选项", "description": "先给可选方向，再确认"},
        {"label": "自由文本", "description": "直接输入，少打断"}
      ]
    }
  ]
}
```

两题调用示例（答案互相约束时才这样写）：
```json
{
  "question_info": [
    {
      "header": "风格",
      "question": "界面风格偏好会锁死后续视觉方向，选哪条？",
      "options": [
        {"label": "紧凑", "description": "信息密度高，适合长会话"},
        {"label": "留白", "description": "更易扫读，适合短交互"}
      ]
    },
    {
      "header": "验证",
      "question": "本轮优先验证哪些环节？（可多选）",
      "multi-option": true,
      "options": [
        {"label": "基础渲染", "description": "先看挂载与布局是否正确"},
        {"label": "键盘交互", "description": "焦点、回车、提交路径"},
        {"label": "回传契约", "description": "答案结构是否可被后续步骤消费"}
      ]
    }
  ]
}
```

写法建议:
- `header` 给 tab、`question` 给题干；禁止只传 `question` 不传 `header`，禁止把整句题干塞进 `header`
- 默认一道题；只有几问必须一次收齐才数组多项，靠 `header` 区分 tab
- 只能选一条路 → 不写 `multi-option` 或写 `false`；可以同时保留几项 → `true`（如「优先验证哪些环节」）
- 选项必须真实不同、互斥且可执行；带 `description` 说明取舍；不要凑一个明显更差的选项来诱导
- 禁止旧入参形态：不要传顶层 `{question, options}`（必须包进 `question_info` 数组）

### 调用后:
- 返回 JSON 数组，即带 `answer` 的同一份 `question_info`
- 每项读 `item.answer.options`（选中的原 option 对象列表）和 `item.answer.user_input`（自行输入字符串，或 `null`）
- **不要**再找 `status`、`answer_type`、`selected_option` 或顶层单独的 `question` / `options` 回答字段
- 调用失败或用户未回答时，不要把空结果当成同意，也不要自行编造用户偏好

### 注意事项:
- 单次题量保持精炼；无关问题不要硬塞进同一次调用
- 自行输入走 TUI 自带输入行；选项盖不住的想法放那里，不要预留「其他」option
