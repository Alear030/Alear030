## command 工具

用途: 在本地 shell 中执行命令，并返回退出码、标准输出 stdout 和标准错误 stderr。

何时使用:
- 用户要求运行一个命令并查看结果时
- 需要查看环境信息、进程、端口、版本号时
- 需要运行脚本、跑测试、装依赖、执行 git 操作时
- 需要通过命令行验证文件是否创建成功时

何时不要使用:
- 只是读取文件内容 → 优先用 file_read
- 只是写入文件内容 → 优先用 file_write
- 只是编辑文件 → 优先用 file_edit
- 只是搜索文件 → 优先用 file_glob / file_grep
- 不要执行需要交互输入的命令（没有 stdin，会一直等到超时）
- 不要执行来源不可信的命令

参数:
- command (必填): 要执行的 shell 命令
- timeout (可选): 超时时间，单位秒，默认 120，最大 120；超过会被钳制到 120 并在结果里告知
- cwd (可选): 本次命令的工作目录。**只对这一次调用生效，不会保留到下一次调用**

工作目录:
- 每次调用都是一个全新的子进程，`cd` 的效果在调用结束后即消失
- 要在别的目录下执行，**用 cwd 参数**，不要靠 `cd X && ...` 去记住目录
- 同一条命令内部的 `cd X && cmd` 仍然有效（同一个 shell 进程内），但仅限这一次

输出:
- stdout 和 stderr 各自有长度上限，超出会保留首尾并在中间标注省略了多少字符
- 因此不要用本工具做全盘扫描式的输出（如递归列出整个磁盘）；先缩小范围，或改用 file_glob / file_grep

安全模型（默认放行，拦截不可逆操作）:
- 绝大多数命令直接放行，包括 npm/pip install、git 提交推送、启动服务等日常开发操作
- 被硬拒的是**不可逆且难以人工挽回**的操作，例如：
  - 递归/通配符批量删除（`rm -rf`、`del /s`、`del *.x`、`rd /s`）
  - 磁盘与系统级破坏（`format`、`diskpart`、`mkfs`、`vssadmin`、`shutdown`）
  - 丢弃工作成果（`git reset --hard`、`git clean -f`）
  - 嵌套执行未经校验的命令（`curl ... | bash`、`find -exec`、`xargs`）
  - 命令替换（`$()`、反引号）
  - 写入系统关键路径（`/etc`、`/boot`、`C:\Windows`、`C:\Program Files`、盘符根目录 等）
- 重定向可以正常用（`>`、`>>`、`<`、`2>&1`），只是**目标不能落在上述系统关键路径**
- 被拒绝时会说明具体原因；这类操作请交给用户手动执行，不要试图换个写法绕过
- 多条命令用 `&&` / `&` / `|` 串联时，**每一段都会各自过一遍检查**

示例:
- 在子目录跑测试 → command=`python -m pytest`，cwd=`D:\proj\app`
  （不要写成 `cd D:\proj\app && python -m pytest`，下次调用就忘了）
- 输出太长时先存文件再定位 → command=`python -m pytest > result.txt 2>&1`
- 操作别处的仓库 → command=`git -C "D:\proj\app" status`

注意事项:
- 命令在本机真实执行，会影响真实文件和环境
- 关注退出码：0 以外都要读 stderr 再决定下一步
- 命令失败时先看清报错，不要原样重试同一条命令
