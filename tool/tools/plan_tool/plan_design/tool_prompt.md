## plan_create 工具

用途: 创建结构化的分步执行计划，将复杂任务拆解为可执行、可验证的步骤序列。调用后计划写入本地文件。与用户确认计划符合预期后，使用 plan_mode_on 工具开启 Plan 执行模式。

何时使用 —— 先回答一个问题：**不做额外调研，我现在能不能用一两句话讲清楚要做什么、按什么顺序做？**

- **能讲清楚** → 不使用本工具，直接向用户说明你的理解并动手执行。
  - 步骤数量、涉及文件多少都不是判断依据。哪怕任务要分两三步、要写好几个文件，只要顺序和验收标准现在就能确定，就不需要 plan 模式。
  - 如果某一步需要调研或搜索（例如先查资料再写东西），只要这不影响你判断整体步骤顺序，就自己直接调用 web_search / file_read 等工具去做，不必为此上升到 plan 模式。
- **讲不清楚** → 使用本工具，让 plan_agent 完成调研并拆解步骤。命中以下任一情形即可：
  - 步骤之间的依赖关系拿不准，需要先系统性分析代码/方案/市场才能确定怎么拆
  - 任务需要成规模的外部信息采集（调研报告、竞品分析、技术选型对比等），且判断步骤顺序依赖这些信息的结果
  - 用户明确要求"制定计划"、"帮我规划一下"
  - 已有计划需要调整（步骤增删、目标变更、补充细节或约束条件）
- 无论上面判断结果如何，以下情形都不使用本工具：
  - 用户明确说"直接做，不用规划"
  - 信息严重不足，连任务目标和边界都不清楚 —— 应先向用户提问，而不是调用 plan_agent 去猜

调用前必须做的事:
- 一次性向用户说明：用一两句话描述你理解的任务目标，并说明接下来打算进入 plan 模式规划步骤。等用户确认"可以"、"就这样"后才调用本工具，未经确认不要调用
- **注意：信息收集和方案搜索由 plan_agent 子 agent 完成，不要自己提前调研或规划步骤**
- **output_file 需要与用户明确确认后才能传入，不允许自行猜测或代替用户决定目录。如果用户没有在对话中明确指定产出目录，本次调用禁止携带 output_file 参数，留空走系统默认目录**

参数:
- plan_title (必填): 计划名称，简洁描述任务目标。例: "重构 memory 模块为图结构"
- task_description (必填): 完整任务描述。包含用户意图目标、任务背景、涉及的文件/模块、用户约束和偏好、预期结果。越详细，计划越精准
- plan_file (可选): 已有计划文件名（不含路径和扩展名）。传入时进入修改模式。
  - 修改模式行为：plan_agent 会读取现有步骤，基于新的 task_description 判断哪些需要保留/修改/删除/新增，返回更新后的完整步骤列表
  - 使用场景：用户对 plan 不满意要求调整、需求中途变更、补充遗漏细节
  - 调用后：主动对比新旧步骤差异并向用户说明变更点，用户可再次修改或确认
  - 不传则创建新计划。
- output_file (可选): 产出物存放目录。**必须经用户明确确认才能传入**——用户在对话中主动指定了具体目录，才可以带这个参数；用户没提，就不要传，不要替用户猜一个路径。不传则默认使用 workspace/plan/{plan_title} 目录。修改模式下不传则沿用已有 plan 的产出目录。

调用后:
- 本工具会启动 plan_agent 自动分析任务、生成分步计划
- 计划写入 session/session_plan/ 目录
- 产出物目录会自动创建，plan 执行阶段每个 step 都会被提示将产出物放置于该目录
- 生成计划后，主动查看计划内容并向用户展示，确认是否符合预期
- 用户确认后，使用 plan_mode_on 工具进入执行模式
